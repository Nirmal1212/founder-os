# Roadmap formats — communicate direction, not promises

A roadmap is a communication tool. The format you pick sets expectations — choose to convey intent without overpromising dates.

## Now / Next / Later (default)
Three horizons, decreasing certainty:
- **Now**: in progress / next up — specific, committed, high confidence.
- **Next**: the following horizon — directional, scoped roughly.
- **Later**: known intentions — themes only, deliberately vague.
Why it wins: communicates sequence and intent, ages gracefully, and doesn't manufacture false date precision. Default to this unless the user needs committed dates.

## Outcome / theme roadmap
Organize around **outcomes**, not features: "Cut time-to-first-value", "Make collaboration trustworthy". Each theme holds candidate features but commits to the *result*. Best for keeping teams problem-focused and giving leadership the why. Pair with Now/Next/Later horizons.

## Timeline / Gantt (only when dates are contractual)
Use when there's a real external commitment (a launch, a customer SLA, a compliance deadline). Costs: implies precision you rarely have, invites date-policing, breaks on the first slip. If required, attach **confidence levels** to dates and revisit on a cadence.

## Rules that apply to any format
- **Themes over feature lists** — a wall of features reads as a backlog, not a strategy.
- **Tie each item to the objective/metric** it serves (from the metric tree).
- **Fewer items, clearly sequenced** beats a comprehensive map nobody can act on.
- **Show the cut line** when relevant — what's explicitly *not* now, and why, prevents the "is X happening?" churn.
- **It's a living direction, not a contract** — say so, and review on a cadence.
