## Product & Engineering

| Skill | Description |
|---|---|
| [founder-os-research](founder-os-research/SKILL.md) | Act as a Senior Product / UX Researcher to run discovery — plan research, write non-leading interview guides, synthesize interviews and signals into themes and jobs-to-be-done, and produce the ICP and personas that downstream product work builds on |
| [founder-os-pm](founder-os-pm/SKILL.md) | Act as a Senior Staff Product Manager to brainstorm use cases, write PRDs, and break PRDs into user stories |
| [founder-os-roadmap](founder-os-roadmap/SKILL.md) | Act as a Senior Product Lead to prioritize a backlog, sequence work into releases, and produce an outcome-oriented roadmap — scoring with RICE or value/effort, deciding what's MVP vs fast-follow vs later, and making the hard scope cuts when time or people are constrained |
| [founder-os-metrics](founder-os-metrics/SKILL.md) | Act as a Senior Analytics / Data PM to define what success looks like and how it gets measured — a north-star metric and supporting metric tree, an event taxonomy with naming conventions for engineering to instrument, and the dashboards/funnels that read from it |
| [founder-os-design-artifacts](founder-os-design-artifacts/SKILL.md) | Act as a Design Director who turns a PRD or use-case set (typically the output of founder-os-pm) into a complete set of foundational design artifacts for an application — target-persona-driven design strategy, a reasoned color palette with tokens, a typography system, and the core design patterns/components |
| [founder-os-architect](founder-os-architect/SKILL.md) | Act as a Senior Staff or Principal Engineer to turn product use cases or a PRD into a High-Level Design (HLD) covering technical requirements, major components, and a recommended tech stack (language/framework, database, cache, queue, and so on) that the user signs off on |
| [founder-os-lld](founder-os-lld/SKILL.md) | Act as a Senior / Staff Engineer to produce the Low-Level Design that turns an HLD into something implementable — API and interface contracts, component/module boundaries and responsibilities, the sequence flows for key use cases, and component-level concerns like validation, error handling, idempotency, concurrency, and observability hooks |
| [founder-os-data-model](founder-os-data-model/SKILL.md) | Act as a Senior Data / Database Engineer to design the persistence layer — the logical data model (entities, attributes, relationships) rendered as an ERD, the physical schema for the chosen database (types, keys, indexes, constraints, partitioning), and the migration / evolution strategy |
